1) Title: Issue with Encoded Song URLs While Fetching MP3 Files

Problem Occurred:
While fetching song files from the local server (`http://127.0.0.1:3000/song`), the extracted `.mp3` links contained encoded characters like `%5C` in the URL. Example output:

`http://127.0.0.1:3000/%5Csong%5Cfilename.mp3`

The `%5C` represents a **backslash (`\`) encoded in URL format**. This happened because the directory listing generated paths using **Windows-style backslashes (`\`)** instead of standard **URL forward slashes (`/`)**.

Because URLs should use forward slashes, the browser encoded the backslashes, resulting in messy and potentially problematic links.

---

Cause:
The server returned file paths using Windows-style path separators:

`\song\filename.mp3`

When converted into URLs, these backslashes were encoded as `%5C`.

---

Resolution:
The issue was resolved by replacing the encoded backslashes in the URLs with forward slashes before storing them in the songs array.

Code Fix:

```javascript
songs.push(element.href.replaceAll("%5C", "/"));
```

This converts the encoded path:

`http://127.0.0.1:3000/%5Csong%5Cfilename.mp3`

into the correct format:

`http://127.0.0.1:3000/song/filename.mp3`

---

Final Result:
After applying the fix, the application correctly retrieves and stores playable `.mp3` song URLs in the `songs` array without encoding issues.

3) Doubt:
Why does
`console.log(e.querySelector(".info"));`
print

`<div> Artemas - i like the way you kiss me (official music video).mp3</div>`

and why does using **`firstChild`** return `#text`, while **`firstElementChild`** returns `<div>`?

---

Answer:

1. `e.querySelector(".info")`
   This selects the element with class **`info`** inside the `<li>`.
   Inside `.info` there is a `<div>` containing the song name, so the browser shows that element in the console.

2.Why `firstChild` returns `#text`
   In the DOM, spaces and line breaks inside HTML are treated as text nodes.
   Because there is whitespace before the `<div>`, the first node inside `.info` becomes a text node, which appears as:

   `#text`

3. Why `firstElementChild` returns `<div>`
   `firstElementChild` ignores text nodes and only returns **HTML elements**.
   Therefore it skips the whitespace text node and returns the first actual element:

   `<div>Song Name</div>`

---

Summary:

| Property            | What it returns                                   |
| ------------------- | ------------------------------------------------- |
| `firstChild`        | First **node** (can be text, comment, or element) |
| `firstElementChild` | First **HTML element only**                       |

So in your case:

 `firstChild` → `#text` (whitespace)
 `firstElementChild` → `<div>` containing the song name.

```javascript
Array.from(document.querySelector(".songList").getElementsByTagName("li")).forEach(e=>{
```

**2. Get all `<li>` elements (songs)**

```javascript
.getElementsByTagName("li")
```

**3. Convert the collection to an array**

```javascript
Array.from(...)
```

`getElementsByTagName()` returns an **HTMLCollection**, not a real array.
`Array.from()` converts it into a **JavaScript array** so we can use array methods like `forEach()`.

**4. Loop through every song**


This runs the function once for **each `<li>` song element**.

Here `e` represents **one song item**.

---

5. Add a click event to each song**

```javascript
e.addEventListener("click", element => { ... })
```

This means:
Whenever the user clicks that song**, run the function inside.

---

6. Get the song name
```javascript
e.querySelector(".info").firstElementChild.innerHTML
```

Flow:

* `e.querySelector(".info")` → finds the `.info` div inside that song
* `.firstElementChild` → gets the inner `<div>` containing the song name

---

**8. Play the song**

The cleaned song name is passed to the **`playMusic()` function**, which loads and plays the audio.

---

Overall Flow

1. Find `.songList`
2. Get all `<li>` songs
3. Convert them to an array

Doubt 1:
Why does `let CurrentSong = new Audio()` not create multiple audio objects?

Answer:
It creates only one audio object because it is declared outside the function.
So the object is created only once when the script loads, and every song click just reuses the same audio player.

If it was written like this:

```javascript
function playMusic(track){
    let audio = new Audio(track)
    audio.play()
}
```

then every function call would create a new audio object, causing multiple songs to play simultaneously.

Juice:

* Outside function → object created once
* Inside function → object created every call

---

Doubt 2:
Why does removing "song/" from this not work?

```javascript
CurrentSong.src = "/song/" + track
```

Answer:
Because the songs are stored inside the song folder.
So the browser must know the correct path to the file.

Correct path example:

```
/song/song1.mp3
```

If you remove "song/":

```javascript

```

the browser searches:

```

```

which does not exist, so the audio doesn't play.

Juice:
`src` must contain the correct folder path to the audio file.

Topic: Closures in Event Listeners

Concept:
A closure in JavaScript happens when a function remembers the variables from the scope in which it was created, even after that outer function has finished executing.

Explanation:
When we create an event listener inside a function, the listener function remembers the variables that were available when it was created. Even if the outer function finishes executing, those variables stay in memory because the event listener might need them later.

Example:

```javascript
function main(){
    let message = "Hello"

    document.querySelector("button").addEventListener("click", ()=>{
        console.log(message)
    })
}

main()
```

Here the event listener remembers the variable `message`.
Even after `main()` finishes running, when the button is clicked later, the listener can still access `message`.

Application in Music Player:
In the music player code, the event listener remembers variables like `playMusic` and `CurrentSong`. So when the user clicks a song later, the listener can still call `playMusic()` and play the track.

Juice:
A closure allows a function to remember variables from its outer scope even after that outer function has finished executing.
